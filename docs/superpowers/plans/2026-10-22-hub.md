# NVIS Documentation Hub Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans, with independent work delegated where interfaces permit. Track each check below.

**Goal:** Deliver the functional local hub described in BUILD_BRIEF.md.

**Architecture:** A shared Python Hub service stores atomic publications in SQLite
and serves both Jinja web views and a stdio MCP adapter. Import explicitly scoped
Markdown and assets from live GitLab or provenance-labelled snapshots.

**Tech Stack:** Python 3.12, FastAPI, Jinja, SQLite FTS5, markdown-it-py, MCP SDK.

**Spec:** ../specs/2026-10-22-hub-design.md

## Global Constraints
- Source documentation stays authoritative in each originating project repo.
- Access control and the future publishing skill remain deferred.
- Keep application changes here; preserve the sibling pipeline and notes.
- Never request secrets pasted into chat.
- No LLM runtime or generated operational documentation.

## Review Focus
- Malformed paths and unsafe content must not escape the publication boundary.
- Failed source acquisition must preserve the last successful publication.
- Changes and deletions must agree across browse, search and MCP after refresh.
- Namespaced nested links and duplicate heading anchors must resolve predictably.
- Empty queries, punctuation, Unicode and missing metadata must have useful results.
